开始使用

先把一次强化跑起来

FlStrengthen 是一个配置驱动的装备强化插件。玩家把符合条件的装备放进强化界面，放入材料，点击按钮，插件根据你写的概率决定成功、失败、降级或损坏。

一句话理解

装备靠“显示名 + 可选 Lore”认领方案，材料靠“显示名 + 可选 Lore”认领身份。配置文件就是这张对照表。

玩家实际会经历什么

  1. 1
    手持装备

    主手只能拿 1 件，并且名字要命中某个强化方案。

  2. 2
    输入命令

    执行 /fls open，装备会暂时放进强化界面。

  3. 3
    放入材料

    必需材料、保护材料、概率加成材料分别放进对应槽位。

  4. 4
    点击强化

    插件检查金币与材料，然后抽随机数并结算结果。

5 分钟测试路线

服务器刚装好插件时，先别急着改配置。按下面顺序确认整条链路是通的。

游戏内依次执行
/fls equipment default 0
/fls material strength-stone 64
/fls material fine-stone 64

拿到“测试武器”和两种测试材料后，手持武器执行：

打开界面
/fls open
默认会检查 Vault 经济

config.yml 默认是 economy.enabled: true。没有 Vault 和经济插件时，把这里改成 false，再执行 /fls reload。

点下去以后应该看到什么

强化前

武器 Lore 出现“强化强度”空进度条，当前等级视为 0。

强化到 1 级后

进度条点亮 2 格，并出现“攻击力 +1、生命值 +2”等方案属性文本。

默认 1 级成功率是 100%，所以第一次测试只要材料、金币和权限都满足，就一定会成功。

配置手册

进阶方案 advancements

强化是在原装备上升级；进阶则是达到条件后消耗旧装备，发放新装备、奖励和命令。一个 YAML 文件里可以放多个进阶方案。

进阶和强化有什么区别

普通强化

装备留在界面里，Lore 等级提高，失败可能保留、降级或损坏。

装备进阶

要求某个强化方案达到指定强度。成功后旧装备被消耗，奖励直接进背包。

完整进阶示例

advancements/default.yml
advancements:
  default-awakening:
    equipment:
      display-name: '&b测试武器%p%'
      material: '*'
      lore-contains: []
    strength-recipe: default
    required-level: 3
    success-chance: 50
    chance-per-extra-level: 5
    fee: 10000
    break-on-failure: false
    materials:
      strength-stone: 5
      fine-stone: 5
    chance-booster:
      material: chance-booster
      max-items: 64
    break-protection-material: break-protector
    rewards:
      items:
        - material: DIAMOND_SWORD
          amount: 1
          name: '&d觉醒·测试武器'
          lore:
            - '&7由 FlStrengthen 进阶系统生成。'
          glow: true
      commands:
        - '[console] say %player% 完成了一次装备进阶'
    broadcast: '&d{player} &7成功进阶了 &f{equipment_name}&7！'

方案 ID 和装备匹配

与强化方案不同，进阶 ID 写在文件内容里。default-awakening 才是方案 ID，文件名只用于组织配置。默认示例要求装备同时满足：

  • 显示名匹配 &b测试武器%p%。
  • 能匹配 strength-recipe: default 的强化方案。
  • 当前强化等级至少为 required-level: 3。

进阶自己也会检查 equipment，并要求关联的强化方案同样认这件装备。这样能避免拿一件只是名字相似、实际没有强化等级的物品来进阶。

成功率怎么算

最终基础概率 = success-chance + (当前等级 - required-level) × chance-per-extra-level

结果最低 0，最高 100。放入概率材料后再往上加，同样最高 100。

默认方案 3 级时是 50%；4 级是 55%；5 级是 60%。required-level 以下根本不能尝试，不会用负数扣概率。

字段速查

字段解释
equipment进阶入口的物品匹配条件，字段与强化方案相同。
strength-recipe用哪个强化方案读取当前等级。必须填已加载的方案 ID。
required-level最低强化等级，低于该值直接提示强度不足。
success-chance刚好达到最低等级时的基础成功率。
chance-per-extra-level每高出最低等级一级，再增加多少成功率。
fee进阶费用，经济开启时扣除。
break-on-failure失败时是否可能损坏旧装备。进阶没有降级逻辑。
materials进阶必需材料 ID 和数量。
chance-booster概率材料定义和单次最多消耗数量。
break-protection-material损坏保护材料 ID。只有失败且开启损坏时才参与。
rewards成功后的物品和命令。
broadcast成功全服消息。

奖励物品怎么写

rewards.items
rewards:
  items:
    - material: DIAMOND_SWORD
      data: 0
      amount: 1
      name: '&d觉醒武器'
      lore:
        - '&7由进阶系统生成'
      glow: true

material 写 Bukkit 材质名。data 用于旧版物品数据值；amount 是数量；glow 只添加隐藏附魔光效。背包放不下时，奖励会掉在玩家脚下，不会消失。

奖励物品的 name 和 lore 不支持运行时占位符。需要在名称里带玩家名等动态内容时，用奖励命令交给其他插件生成物品，或修改插件代码扩展。

成功后发生什么

  1. 消耗旧装备

    界面装备槽里的原装备被移除。

  2. 发放奖励

    按 rewards.items 的顺序给物品，放不下就掉落。

  3. 执行命令

    按 rewards.commands 执行，支持 [console]、[player]。

  4. 广播与关界面

    发送 broadcast，随后关闭进阶界面。

奖励命令也支持 %player%、%level%、%equipment_name%。%level% 是进阶时的原装备强度。

失败时发生什么

break-on-failure: false 时，旧装备保留，材料和金币正常消耗。true 时会先检查损坏保护；保护失败则装备消失。进阶没有“失败降级到某个强度”的配置。

配置手册

界面 gui

强化和进阶各有一个界面布局文件。槽位数字与 Bukkit 背包一致，从 0 开始：第一行第一格是 0，第一行第九格是 8，第二行第一格是 9。

两个文件，同一套结构

plugins/FlStrengthen/gui/

├─ strengthen.yml/fls open

└─ advance.yml/fls advance

文件名由 config.yml 里的 gui.strengthen-layout 和 gui.advance-layout 决定。想换界面风格时，可以复制一份再切文件名。

默认 54 格界面地图

装备 必需材料 保护材料 概率材料 执行按钮 信息物品

图上数字就是配置槽位。默认设备在 13，材料在 19 到 25，保护在 29 和 30，概率材料在 32 和 33，按钮在 40，信息纸张在 4。

槽位字段

字段默认作用
title界面标题支持 & 颜色代码。
size54界面格子数。插件限定在 9 到 54，并向上补齐为整行。
equipment-slots[13]装备展示位。当前实现只使用列表第一项放实际装备。
material-slots[19...25]必需材料可以放入的范围。
protection-slots[29, 30]损坏保护和降级保护共用这些格子。
boost-slots[32, 33]概率加成材料槽。
button-slot40点击后执行强化或进阶的格子。
message-slots[4]动态信息物品显示的格子，可以配多个。

装饰、按钮和信息物品

strengthen.yml 片段
button-item:
  material: ANVIL
  data: 0
  name: '&c&l点击强化'
  lore:
    - '&7当前等级: &f%level%'
    - '&7成功率: &e%chance%%'
    - '&7费用: &6%money%'
  glow: true

message-item:
  material: PAPER
  name: '&e强化信息'
  lore:
    - '&7装备: &f%equipment_name%'
    - '&7所需材料: &f%requirements%'

filler-item 会填满所有没被其他功能占用的格子。它只是装饰，关闭界面时不会返还。button-item 放在按钮槽，message-item 会复制到每个信息槽。

三类物品都支持 material、data、amount、name、lore、glow。在 1.12 需要物品数据值时可写 data: 15；材质也可以使用 'LEGACY:160'。

按钮和信息物品可用的占位符

%equipment_name%装备显示名，去掉颜色

%level%当前强化等级

%next_level%下一等级

%chance%计算加成后的当前成功率

%money%配置中的费用

%requirements%材料名称和数量

%break%失败是否可能损坏，显示“是”或“否”

%downgrade%失败降低几级

%required_level%进阶最低强度

百分比符号本身要写两个：%chance%% 会显示成“75%”。前面的 %chance% 是占位符，最后一个是普通百分号。

界面操作规则

  • 主装备槽锁定，玩家不能直接拿走或换入另一件装备。
  • 界面内所有拖拽都会被取消，防止把物品拖到奇怪的位置。
  • 材料槽只接受已登记、且分类匹配的物品。
  • 在玩家背包按住 Shift 点击材料，会尝试放进第一个合适的空槽。
  • 关闭界面时只返还装备、材料、保护和加成槽，按钮和装饰不会被刷出来。
槽位不能重叠

装备、材料、保护、加成、按钮和信息槽尽量各用各的。虽然插件会按固定顺序处理，但重叠配置会让界面行为很难理解，也容易误操作。

运行机制与安全

这一页解释“点一下按钮后到底发生了什么”。理解顺序后，失败保护、材料消耗和概率预览就不会看起来像随机乱扣。

一次强化的完整顺序

  1. 检查会话和冷却同一玩家只能有一个活动界面，默认 300 毫秒内不能重复执行。
  2. 重新确认装备装备槽必须仍是同一件、数量为 1，并且继续匹配方案。
  3. 只检查，不先扣先确认目标等级、材料和金币足够。任何一项不足都不会进入抽奖。
  4. 计算预览概率基础成功率加概率材料，最终限制在 0 到 100。
  5. 触发尝试事件其他插件可以在这一步取消强化。
  6. 保存快照并扣费保存界面物品快照，再扣金币和必需材料。
  7. 消耗概率材料并判定只消耗补满成功率所需的材料，然后生成 0 到 100 的随机数。
  8. 结算成功或失败更新 Lore；失败时再检查损坏、降级和保护材料。
  9. 触发完成事件把成功、保留、降级、保护或损坏结果交给监听器。

失败结果对照表

配置情况失败后材料与金币
不损坏，降级 0 级装备和等级都保留照常消耗
不损坏，降级 1 到 N 级等级降低，最低到 0照常消耗；降级保护可介入
允许损坏，保护成功装备保留在当前等级必需材料、金币、保护材料照常消耗
允许损坏，保护失败装备从界面消失必需材料、金币、保护材料照常消耗
允许损坏，同时又配置降级先判定损坏；没坏再判定降级两类保护可能都需要

普通失败不是“插件出错”，因此不会回滚。只有处理过程中抛出未预期异常时，插件才恢复界面快照并退回已经扣除的金币。

保护材料怎么生效

进入对应失败分支后，插件会把保护槽里所有匹配该保护 ID 的物品一次性消耗，把每件物品的概率相加，再抽一次。

3 件保护石，每件 10% → 总保护率 30%

抽中 → 本次损坏或降级被挡住；没抽中 → 正常损坏或降级

保护物品无论判定成功还是失败都会消耗。若某个等级同时可能损坏和降级，先处理损坏保护；装备没被损坏，再处理降级保护。

概率材料为什么不会“吃满”

假设基础成功率 90%，每件祝福材料加 5%，槽里放了 10 件。插件只会消耗 2 件把成功率补到 100%，剩下 8 件留在界面里。

基础 90%

预览显示 90%。

放入 10 件，每件 +5%

预览显示 100%，但只计算到上限。

点击执行

消耗 2 件，剩余 8 件关闭界面时退回。

max-items 是单次最多计入多少件。即使槽里放得更多，预览和消耗都只按这个上限计算。

概率边界

所有概率先限制到 0 到 100。判定使用 [0, 100) 的随机数，因此边界行为明确：

  • 0 永远失败，不会出现极小概率成功。
  • 100 永远成功，不会因为随机数刚好 100 失败。
  • 写小数也可以，例如 12.5 表示 12.5%。
  • 写负数按下限 0 处理，写超过 100 按上限 100 处理。

为什么关闭界面能退物品

打开界面时，插件先给这次操作建立独立会话，并记录玩家、装备、布局和界面容器。它只处理自己创建的界面，不会把普通箱子点击误判成强化操作。

关闭、插件禁用或默认重载时，插件只返还内容槽位中的物品。装饰玻璃、按钮和信息纸张由插件生成，不在返还范围内，这能挡住通过关闭界面复制按钮物品的问题。

性能与重载

Bukkit 背包操作都在主线程完成。配置解析完成后会整体替换数据引用，避免玩家操作到一半撞上新旧配置混合的状态。默认重载会先关闭活动界面，所以重载期间不会保留旧会话。

插件没有为每个玩家启动计时器，也没有后台线程轮询。日常开销主要来自打开界面、更新预览和点击结算，适合普通生存服的材料规模。

当前版本不做真实属性修改

原版攻击力、生命值等不会因为 Lore 里的文字自动变化。需要真实数值时，请用成功命令对接属性插件，或让玩法本身以 Lore 为结算依据。

命令与权限

主命令是 /flstrengthen，日常可以简写成 /fls。管理命令主要用于生成测试物品、查看版本和重载配置。

全部命令

命令权限用途
/fls openflstrengthen.use打开主手装备的强化界面。
/fls advanceflstrengthen.advance打开主手装备的进阶界面。
/fls material <ID> [数量]flstrengthen.admin生成测试材料，数量限制 1 到 64。
/fls equipment <方案ID> [等级]flstrengthen.admin生成某个方案的测试装备。
/fls reloadflstrengthen.admin关闭活动界面并重新读取全部 YAML。
/fls version无查看当前插件版本。
/fls help无显示游戏内帮助。

别名有 /flstrengthen、/fls、/wqh。三个写法执行的是同一套命令。

常用示例

给玩家自己生成测试内容
/fls equipment default 0
/fls equipment default 5
/fls material strength-stone 64
/fls material chance-booster 16

/fls equipment default 5 会直接生成 5 级装备，方便测试满级提示和进阶。传入超出方案范围的等级时，插件会夹到 0 到最高等级之间。

/fls material 和 /fls equipment 必须由玩家执行，因为生成物会进入玩家背包。控制台可以正常执行 /fls reload 和 /fls version。

权限默认值

flstrengthen.use默认所有玩家拥有，允许打开强化界面。

flstrengthen.advance默认所有玩家拥有，允许打开进阶界面。

flstrengthen.admin默认仅 OP 拥有，允许生成物品和重载配置。

LuckPerms 示例

控制台或游戏内
/lp group default permission set flstrengthen.use true
/lp group default permission set flstrengthen.advance true
/lp user Steve permission set flstrengthen.admin true

如果普通玩家能打开命令却没有匹配方案，先检查装备显示名和 Lore，不要第一时间怀疑权限。权限只决定能不能执行命令，不决定装备是否进入某个方案。

Tab 补全

插件会根据权限补全子命令，也会为材料命令补全材料 ID、为装备命令补全方案 ID。输入到一半再按 Tab 即可，不需要去翻配置文件找 ID。

常见问题与排错

先看控制台的加载数量，再看物品能不能匹配，最后看材料、金币和槽位。大多数问题都在这四步之内。

控制台报错→ 方案数量→ 装备匹配→ 材料与经济

配置明明改了，为什么没生效？

改的是 plugins/FlStrengthen/ 下的文件，并且执行了 /fls reload 吗？如果改的是源码里的 src/main/resources，那只会在重新构建 JAR 后影响新生成的默认文件；服务器运行时读取的是插件数据目录。

插件不会覆盖已经存在的 YAML。想恢复默认配置，应先备份，再移走旧文件后重启，让插件重新生成。

提示加载 0 个方案，怎么查？

  1. 看文件位置

    强化文件必须在 recipes/，扩展名必须是 .yml。

  2. 看等级是否连续

    max-level: 5 就必须有 1、2、3、4、5，一个都不能少。

  3. 看材料 ID

    方案里引用的每个材料都必须在 materials.yml 存在。

  4. 看 YAML 缩进

    层级只能用空格，不要混 Tab。列表项前的 - 要与内容对齐。

被跳过的方案会在控制台给出文件名和原因。先搜索 JAR 名或 Skipped invalid。

装备就是打不开，提示没有匹配方案

按顺序检查三个条件：装备必须有自定义显示名；显示名去掉颜色后要完整匹配模板；如果写了 lore-contains，每一条 Lore 都必须存在。只满足其中一个不够。

先做一个不会认错的测试物品

执行 /fls equipment default 0。这个命令生成的装备一定能匹配默认方案。如果它能打开，就说明插件正常，问题在你自己物品的名字或 Lore。

材料放不进槽位

  • 材料是否有自定义显示名，并且与 display-name 匹配。
  • category 是否与槽位类型一致。例如强化石不能放进概率材料槽。
  • 物品是否先命中了更早的另一条材料定义。
  • 保护材料槽和加成材料槽在界面配置中是否真的存在。
  • 若使用 Shift 点击，目标分类的槽位是否已经放满。

一直提示经济系统不可用

economy.enabled: true 时，只要本次费用大于 0，插件就要求 Vault 和经济插件都正常。安装 Vault 与经济插件，或关闭经济开关。

如果已经关闭经济却仍看到收费，先区分“界面预览写着费用”和“余额真的少了”。关闭经济后实际扣款为 0。

按钮上的成功率和配置不一样

按钮显示的是“基础成功率 + 当前概率材料加成”，不是只读 success-chance。把加成槽里的物品拿出来，再观察数字是否回到基础值。

如果基础值是 100，放不加概率材料也是 100。如果基础值是 0，必须靠材料或其他插件事件才有可能成功；插件本身不会偷偷给保底。

保护石怎么全没了？

保护材料不是按“生效几件扣几件”，而是进入对应失败分支后，把槽内所有匹配物品一次性消耗，再把概率相加做一次判定。数量越多，总保护率越高，但无论成功失败都会全部消耗。

更新配置后，旧装备等级变成 0 了

插件通过当前 level-display 生成的 Lore 文本来识别等级。如果改了模板、进度条长度或填充字符，旧装备上那一行就匹配不上新模板，于是被当成 0 级。

已经上线的方案尽量冻结等级显示格式。确实要改时，先准备旧装备迁移方案，例如用命令批量替换 Lore。

Lore 写着攻击力 +15，为什么伤害没变？

attributes 是纯文本，不是原版 AttributeModifier。FlStrengthen 负责写 Lore 和触发命令，不负责修改剑的基础伤害、额外生命或暴击系统。

要产生真实效果，可以在 success-commands 里调用属性插件、RPG 插件或自定义脚本。如果服务端已有按 Lore 计算属性的系统，则继续遵守那套系统的格式要求。

关闭界面后物品去哪了？

装备、必需材料、保护材料和概率材料会尝试放回背包。背包满时物品掉落在玩家脚下。按钮、信息纸张和填充玻璃由插件生成，不会返还。

如果重载或禁用插件时界面还开着，插件也会先关闭并返还内容。极端情况下操作背包抛出异常，应查看控制台并停服检查，不要继续让玩家批量点击。

reload 和重启有什么区别？

/fls reload 只重新读取 YAML，不重新加载 Java 类。改配置用它，换 JAR 必须完整重启。重载失败时，先解决控制台指出的 YAML 或引用错误，再重复执行。

Paper 1.20 的 legacy plugin 警告要处理吗？

通常不用。插件为了兼容 1.12 没有在 plugin.yml 写 api-version，所以新版 Paper 会提醒一次。只要控制台随后显示 FlStrengthen 已启用并加载方案，就不影响运行。

插件完全没启用

  1. 确认文件

    JAR 是否放在 plugins/，文件名是否完整，文件大小是否正常。

  2. 确认 Java

    插件产物是 Java 8 字节码。服务端的 Java 版本应满足服务端本身要求。

  3. 搜索首个报错

    不要只看最后一行。找到第一次出现 FlStrengthen 的异常和它下面的 Caused by。

  4. 排除配置损坏

    临时移走插件配置目录并重启，让插件重新生成默认文件，再判断是不是旧 YAML 导致。

广播或命令里变量没有替换

命令使用百分号：%player%、%level%、%equipment_name%。广播使用大括号：{player}、{level}、{equipment_name}。两套语法不要混用。

[op] 前缀被安全策略拦截，会在控制台打印警告并且不执行。需要以玩家身份运行时写 [player]，其余情况写 [console]。

参考

开发者事件 API

插件提供四个同步 Bukkit 事件：强化尝试、强化完成、进阶尝试、进阶完成。适合接入活动倍率、次数限制、统计、日志和成就系统。

事件列表

事件可取消能拿到什么
FlStrengthenAttemptEvent是玩家、方案、当前等级、下一等级、预览成功率和费用。
FlStrengthenCompleteEvent否玩家、方案和最终结果。
FlAdvanceAttemptEvent是玩家、进阶方案、当前强度和预览成功率。
FlAdvanceCompleteEvent否玩家、进阶方案和最终结果。

尝试事件在扣金币和材料之前触发，所以在这里取消不会损失物品。完成事件在结算结束后触发，不能用它撤销已经发生的失败。

上面的结果对象包含 8 种状态，但完成事件只在真正进入结算后发出。被取消、条件无效或处理异常时，流程会直接返回，因此完成事件监听器通常只会看到 SUCCESS 或各种 FAIL_* 结果。

完成结果的几种状态

SUCCESS成功

FAIL_KEPT失败但装备保留

FAIL_DOWNGRADED失败并降级

FAIL_PROTECTED保护材料挡住失败

FAIL_DESTROYED失败并损坏

CANCELLED被事件取消

INVALID条件不足或装备变化

ERROR异常并执行回滚

用 result.isSuccess() 快速判断成功，或读取 getOutcome() 做更细的统计。getPreviousLevel() 和 getResultLevel() 分别表示操作前后等级。

监听示例

下面这个监听器会取消“预览成功率低于 10%”的尝试，并在成功后打印一条日志：

StrengthListener.java
package example;

import cn.fl.strengthen.api.FlAttemptResult;
import cn.fl.strengthen.api.FlStrengthenAttemptEvent;
import cn.fl.strengthen.api.FlStrengthenCompleteEvent;
import org.bukkit.event.EventHandler;
import org.bukkit.event.EventPriority;
import org.bukkit.event.Listener;

public final class StrengthListener implements Listener {
    @EventHandler(priority = EventPriority.HIGHEST,
            ignoreCancelled = true)
    public void onAttempt(FlStrengthenAttemptEvent event) {
        if (event.getChance() < 10D) {
            event.setCancelled(true);
        }
    }

    @EventHandler
    public void onComplete(FlStrengthenCompleteEvent event) {
        if (event.getResult().getOutcome()
                == FlAttemptResult.Outcome.SUCCESS) {
            event.getPlayer().sendMessage("强化成功");
        }
    }
}
在主类 onEnable() 注册
getServer().getPluginManager().registerEvents(
        new StrengthListener(), this);

接入时注意

  • 四个事件都是同步事件，需要操作 Bukkit 物品或玩家状态时保持主线程规则。
  • 尝试事件看到的成功率包含当前界面里的概率材料，但此时还没有扣材料。
  • 完成事件的监听器抛异常会被插件捕获并记录，不会让整个服务器调度中断。
  • API 类和模型类都在 FlStrengthen JAR 中。开发插件时按普通软依赖方式编译，并在服务器上安装 FlStrengthen。
事件适合扩展，不适合偷偷改数值

尝试事件没有修改成功率的 setter，只提供预览值和取消能力。需要动态倍率时，建议在事件中判断条件，再通过你自己的配置或命令系统实现；不要假设修改展示值会改变最终抽奖。

配置手册

材料 materials.yml

材料文件相当于“身份证登记处”。强化方案只写材料 ID，例如 strength-stone；到底长什么样的物品才算这个 ID，由这里决定。

一份能直接看懂的配置

materials.yml
materials:
  strength-stone:
    category: MATERIAL
    display-name: '&b测试强化石'
    material: '*'
    lore-contains: []

  chance-booster:
    category: BOOST
    display-name: '&d测试祝福材料'
    material: '*'
    lore-contains: []
    bonus-key: '强化成功几率'
    default-bonus: 5

第一条告诉插件：显示名是“测试强化石”的物品，ID 就是 strength-stone，可以放进材料槽。第二条除了身份，还告诉插件：每件最多增加 5% 成功率。

每个字段到底管什么

字段必填解释
category建议能放进哪类槽位：MATERIAL、PROTECTION、BOOST、ANY。
display-name是物品显示名模板。支持 %p% 通配，比较时忽略颜色。
material否Bukkit 材质名；'*' 表示不限制物品类型。默认就是 '*'。
lore-contains否物品必须同时包含这些 Lore 文本。适合防止普通物品只改个名字就冒充材料。
bonus-key否从 Lore 中找到这个关键词，并读取关键词后面的第一个数字作为概率。
default-bonus否没找到关键词数值时，每件物品使用多少概率。默认 0。

四种分类怎么选

MATERIAL必需材料。例如强化石、精炼石。

PROTECTION保护材料。根据方案决定保护损坏或保护降级。

BOOST概率材料。放得越多成功率越高，达到目标后只会消耗需要的数量。

ANY三类槽位都能放。方便，但更容易发生定义冲突。

显示名匹配：%p% 是通配符

插件匹配的是“去掉颜色代码后的完整显示名”，并且不区分英文大小写。%p% 可以代表任意文本，也可以代表空文本。

'&b强化石%p%'匹配“强化石”“强化石 +1”“强化石·高级”
'&c[%p%]保护石'匹配“[初级]保护石”“[副本]保护石”
'强化石'只匹配显示名完全等于“强化石”的物品
没有显示名的物品不会命中

材料匹配要求物品已有自定义显示名。即使材质和 Lore 都对，没有显示名也不能放入任何特殊槽位。

用 Lore 增加可信度

只靠名字很容易被同名物品冒充。建议给正式材料加一行固定 Lore，并同时写进配置：

材料定义
  strength-stone:
    category: MATERIAL
    display-name: '&b服务器强化石'
    material: '*'
    lore-contains:
      - '&8FlStrengthen 材料'
    bonus-key: '强化成功几率'
    default-bonus: 5

lore-contains 是“全部包含”而不是“任意一条包含”。写了三行，物品就必须同时拥有这三段文字。颜色代码会被忽略，文字内容必须出现。

概率数字从哪里读

假设物品 Lore 写着 强化成功几率: 8，配置关键词是 强化成功几率，那么每件算 8%。百分号可写可不写，插件读取的是关键词后面的第一个数字。

找到关键词和数字

该件物品的概率等于数字，例如 +8%。

只有关键词，没写数字

使用 default-bonus。

连关键词都没有

同样使用 default-bonus。

同名冲突时按文件顺序取第一个

插件会按 materials.yml 中从上到下的顺序查找。一个物品同时符合多个定义时，只认第一个。请让定义尽量具体，尤其是不要先放一个过于宽松的 %p% 定义，否则后面的定义可能永远匹配不到。

material 怎么写才不跨版本翻车

材料识别使用的是当前服务端返回的 Bukkit 材质名，并且要求完全一致。跨版本最稳的做法是：材料正式物品用专属显示名和 Lore，识别时写 material: '*'。

写法可用于说明
material: '*'所有版本不检查材质，只检查显示名和 Lore，推荐用于自定义材料。
material: DIAMOND_SWORD1.12 - 1.20基础材质名在各版本中比较稳定。
material: STAINED_GLASS_PANE主要在 1.121.13 起名称发生变化，例如白色玻璃板是 WHITE_STAINED_GLASS_PANE。
LEGACY:160仅创建物品处可用于 GUI 和进阶奖励的材质字段，用于按旧数字 ID 创建物品；不要把它当成材料匹配名。
一条规则省掉大多数兼容问题

材料永远写 material: '*'，再用固定显示名和专属 Lore 判断。这样同一个配置文件从 1.12 换到 1.20，不需要重新查方块枚举。

配置手册

强化方案 recipes

recipes/ 下的每个 YAML 就是一个完整的强化方案。文件名去掉 .yml 后就是方案 ID，例如 weapon.yml 的方案 ID 是 weapon。

文件放在哪里

plugins/FlStrengthen/recipes/

├─ default.yml方案 ID：default

├─ weapon.yml方案 ID：weapon

└─ armor.yml方案 ID：armor

文件会按名称排序加载。多件装备同时符合多个方案时，插件取第一个匹配项，所以应尽量用专属 Lore 或更明确的显示名区分方案。

一份两分钟就能看懂的小方案

recipes/weapon.yml
equipment:
  display-name: '&b精炼剑%p%'
  material: DIAMOND_SWORD
  lore-contains:
    - '&8FlStrengthen 装备'

marker: '&e----[&c强化属性&e]-----'
max-level: 2

level-display:
  mode: NUMBER
  template: '&b强化等级: &e{level} / 2'

protection:
  break-material: break-protector
  downgrade-material: downgrade-protector

chance-booster:
  material: chance-booster
  max-items: 64

levels:
  '1':
    fee: 100
    success-chance: 100
    break-on-failure: false
    downgrade-levels: 0
    materials:
      strength-stone: 1
    attributes:
      - '&a攻击力: &c+1'
    success-commands: []
    broadcast: ''
  '2':
    fee: 200
    success-chance: 60
    break-on-failure: true
    downgrade-levels: 1
    materials:
      strength-stone: 2
      fine-stone: 1
    attributes:
      - '&a攻击力: &c+3'
      - '&a生命值: &c+5'
    success-commands:
      - '[console] say %player% 的武器强化到了 %level% 级'
    broadcast: '&e{player} &7把装备强化到了 &e{level} 级！'

equipment：什么装备能进这个方案

字段示例解释
display-name'&b精炼剑%p%'必须匹配的显示名模板。%p% 可以代表任意后缀，颜色不参与比较。
materialDIAMOND_SWORD限制 Bukkit 材质；写 '*' 表示不限制。
lore-contains['&8FlStrengthen 装备']装备必须拥有的 Lore。强烈建议写一条专属标识，防止同名普通剑混进强化。
识别装备时，显示名是硬条件

装备也必须拥有自定义显示名。只改 Lore、没改名字的普通钻石剑不会进入方案。

max-level 与 levels：升级路线

max-level: 2 表示最高 2 级。你必须连续写出 '1' 和 '2' 两个等级。少写一级、跳号或写超过上限，整个方案会被跳过并在控制台提示。

YAML 里把等级数字加上引号最稳：'1':。没加引号通常也能读，但引号可以明确告诉 YAML：“这是键名，不是普通数字”。

每个等级里的字段

字段示例实际效果
fee200从当前等级升到这一级要扣多少金币。经济关闭时不扣。
success-chance60基础成功率，范围 0 到 100。0 必失败，100 必成功。
break-on-failuretrue失败后是否进入损坏判定。保护材料只在这个开关为 true 时有意义。
downgrade-levels1失败且装备没有损坏时，降低几级；最低降到 0。
materialsstrength-stone: 2升到这一级必须消耗的材料 ID 和数量。
attributes攻击力 +3成功后写入 Lore 的属性文本。它不会自动修改原版战斗属性。
success-commands[console] ...成功后执行命令。可以对接其他 RPG 或属性插件。
broadcast{player} ...成功后发送全服消息；留空就不广播。

level-display：等级写在 Lore 里长什么样

插件不靠“第几行数字”猜等级，而是把每个等级都渲染成一行文本，再拿装备 Lore 逐行精确比较。改显示模板后，旧装备如果还写着旧模板，可能被重新视为 0 级。上线后不要随意改这一段的格式。

NUMBER 数字

mode: NUMBER
template: '&e强化 +{level}'

显示“强化 +0”“强化 +1”。数字直观，适合等级很多的方案。

BAR 进度条

mode: BAR
template: '&b强度 [{bar}]'
bar-length: 10
filled: '■'
empty: '□'

默认效果是 10 格进度条。填充格数按当前等级占最高等级的比例计算。

WORDS 文字

mode: WORDS
template: '&b强化: &e{word}'
words: ['零', '壹', '贰']

按等级从数组取词。数组不够长时，最高等级会重复使用最后一个词，真的需要更多词就补齐。

三种模式都支持在同一模板里混用 {level}、{bar} 和 {word}。注意没有 {max} 占位符，最高等级要写成固定文字。

marker：属性区域的分隔线

建议保留 marker。第一次成功时，插件会把这行分隔线放进 Lore，再把等级行和完整属性组插到它下面。以后升级时只替换这块由插件管理的内容，不会乱删玩家原有的其他 Lore。

protection 与 chance-booster

引用 materials.yml 里的 ID
protection:
  break-material: break-protector
  downgrade-material: downgrade-protector

chance-booster:
  material: chance-booster
  max-items: 64

break-material 只在 break-on-failure: true 时参与。降级保护只在确实要降级时参与。概率材料放在加成槽，计算时只消耗达到 100% 所需的件数，并且受 max-items 限制。

success-commands 与三类占位符

每条命令可以写 [console] 或 [player]。不写前缀时默认按控制台执行。[op] 会被明确拦截，避免配置被植入后给玩家临时 OP。

[console] say %player% 强化到了 %level% 级 [player] msg %player% 你的 %equipment_name% 变强了

命令支持 %player%、%level%、%equipment_name%。广播支持 {player}、{level}、{equipment_name}。这两套括号不一样，别写混。

attributes 是整组替换

2 级不要只写“新增一行”。每个等级的 attributes 都应该是这一级完整的属性列表，插件会移除上一级旧属性并写入新列表。

开始使用

跑通第一次强化

这一页只做一件事：用默认配置从 0 强化到 1。成功一次后，你会同时理解装备识别、材料扣除和 Lore 更新。

1. 准备测试装备和材料

需要 OP 权限
/fls equipment default 0
/fls material strength-stone 64
/fls material fine-stone 64
命令你会拿到用途
/fls equipment default 0显示名为“测试武器测试”的钻石剑default 是方案 ID，0 是初始等级。
/fls material strength-stone 6464 个测试强化石强化 1 级需要 1 个。
/fls material fine-stone 6464 个测试精炼石2 级以后会用到。

测试材料默认生成成石头，因为 materials.yml 里的 material: '*' 表示不限原版材质。插件实际认的是显示名和 Lore，不是你背包里的物品类型。

2. 手持武器打开界面

玩家命令
/fls open

主手只能拿 1 件武器。如果武器堆叠成一组，插件会拒绝打开，避免强化后数量无法判断。

3. 把强化石放进材料槽

默认界面中，装备在第 13 格，材料区是第 19 到 25 格，执行按钮在第 40 格。槽位从 0 开始，所以 19 就是第四行第二格。

把 测试强化石 放进材料区。上方纸张会显示当前等级、目标等级、成功率、费用和所需材料；按钮会显示同样的关键信息。

4. 点击“点击强化”

1 级成功率是 100%，费用 100 金币，需要 1 个 strength-stone。条件满足时会直接成功。

强化后 Lore

强化强度 [■■□□□□□□□□]

装备下方还会出现方案中配置的属性文本，例如：

&a攻击力: &c+1 &a生命值: &c+2
属性文本不会修改原版攻击力

attributes 只负责写 Lore。要让这些数字真的影响战斗，需要通过 success-commands 对接属性、技能或其他 RPG 插件；如果你的服务端只看 Lore，也应按实际玩法设计数值。

5. 关闭界面

按 Esc 关闭。装备、剩余材料、保护材料和概率材料会被退回背包；背包满时掉落在玩家脚下。装饰玻璃、按钮和信息纸张不会退给玩家。

配置手册

主配置 config.yml

这里管的是插件整体行为：经济要不要启用、连点冷却多久、重载时怎么处理已打开的界面。它不负责具体强化概率，概率在 recipes 里。

完整默认配置

plugins/FlStrengthen/config.yml
settings:
  action-cooldown-ms: 300
  close-sessions-on-reload: true
  debug: false

economy:
  enabled: true

gui:
  strengthen-layout: strengthen.yml
  advance-layout: advance.yml

files:
  messages: messages.yml

字段解释

字段默认人话解释
action-cooldown-ms300同一个玩家两次点击执行按钮之间至少隔多久，单位是毫秒。它用于挡住高频连点。
close-sessions-on-reloadtrue重载配置前先关闭所有强化界面并退还物品，避免玩家继续操作旧配置。
debugfalse开启后，交易异常会把完整堆栈打印到控制台。排查问题时临时改 true。
economy.enabledtrue是否真的收取 fee。开启后需要 Vault 和可用的经济插件。
gui.strengthen-layoutstrengthen.yml强化界面读取 gui/ 下的哪个文件。
gui.advance-layoutadvance.yml进阶界面读取 gui/ 下的哪个文件。
files.messagesmessages.yml提示消息文件的位置。

经济开关怎么选

有 Vault 经济

保持 true。强化和进阶会检查余额、扣除费用；扣款失败时不会继续消耗材料。

不用金币

改为 false。所有方案照常运行，但不会检查或扣除金币。

费用预览与真实扣款是两件事

关闭经济后，真实扣款为 0。当前版本的界面 %money% 仍按方案里的 fee 显示配置数字，因此测试时不要只凭按钮上的金币数字判断是否扣款。

什么时候需要重载

改完任意 YAML 后，在游戏内或控制台执行：

管理员命令
/fls reload

成功时会提示重新加载了多少个强化方案和进阶方案。看到“配置重载失败”时，保留旧运行数据并检查控制台；常见原因是 YAML 缩进错误、概率写成文本、引用了不存在的材料 ID，或强化等级没有从 1 连续写满。

改 JAR 不靠 reload

/fls reload 只重读配置文件。替换插件 JAR 后必须完整重启服务端。

开始使用

安装与兼容

插件只调用 Bukkit API，不使用 NMS，因此同一份 JAR 可以覆盖 1.12 到 1.20 的服务端。材质名、Lore 和界面都按服务端当前版本解析。

支持范围

项目支持情况说明
Minecraft1.12 - 1.20使用 Spigot 1.12.2 API 编译，产物为 Java 8 字节码。
服务端Paper / Mohist / Spigot适用于保留 Bukkit API 的服务端。
实测启动Paper 1.12.2、1.20.1两端均完成加载与默认配置生成验证。
经济Vault 可选不用经济时关闭 economy.enabled 即可。

Paper 1.20 看到“插件未声明 api-version”的提示属于预期现象。为了兼容 1.12，plugin.yml 故意没有写这个新版字段。

安装步骤

  1. 放入服务端

    把 target/FlStrengthen-1.0.0.jar 放进服务端的 plugins/ 目录。

  2. 完全重启

    第一次安装不要只执行 reload，停止服务端后重新启动。

  3. 检查控制台

    应看到加载了 1 个强化方案和 1 个进阶方案。

  4. 选择经济模式

    有 Vault 就保持默认；没有 Vault 就关闭经济检查。

第一次启动生成的文件

plugins/FlStrengthen/

├─ config.yml总开关

├─ messages.yml提示文字

├─ materials.yml物品身份表

├─ recipes/每个文件一个强化方案

├─ advancements/进阶方案

└─ gui/界面布局

没有 Vault 怎么办

plugins/FlStrengthen/config.yml
economy:
  enabled: false

关闭后，插件不会扣除金币，也不会因为缺少经济服务拦截强化。方案里的 fee 仍可保留，方便以后重新启用经济。

更新插件时

替换 JAR 后完整重启最稳妥。只改 YAML 时可以使用 /fls reload；默认会先关闭所有已打开的强化界面，并把玩家的装备和材料退回背包，避免旧界面继续引用旧配置。

不要直接删除配置目录做“升级”

插件不会覆盖已经存在的 YAML。想保留你的方案、材料 ID 和玩家装备识别规则，就先备份再修改。
